execution and QEMU do not establish physical Pi acceptance.

## Comparison and integration decision

| Contract | Our x86_64 v11 | Jonx AArch64 | Mainline v1 | Decision/status |
|---|---|---|---|---|
| Compiler/sysroot | 1.100 nightly, private source copy | 1.98 nightly, vendored rust-src | 1.98.1 stage1 compiler and std | Explicit pins initially; one compiler remains an integration gate |
| Target/link/CRT | GCC, CrtBase wrappers, ELF ET_REL | large-model ELF, C harness + collect-aros, posixc | built-in targets, target C driver wrapper | Reuse Jonx ARM code; never use v11 symbol names on v1 |
| libc structures | measured v11 SDK | C fs bridge; handwritten time/pthread declarations | generated SDK bindings | Compile header assertions for the selected SDK before link |
| Atomics/TLS | 64-bit atomics, pthread-key TLS | target advertises 128-bit atomics, pthread-key TLS | no ELF TLS | CPU target properties must be checked separately |
| Threads/sync | unix std + v11 lifecycle patches | aros PAL + pthread C bridge | unix PAL, runtime claims hosted x86 only | Shared acceptance: spawn/join, counter and channel |
| Clocks | SDK libc timespec | i32 seconds/i64 nanoseconds, clocks 0/2 | posixc | Match headers, require actual monotonic progress |
| Allocator | unix libc | custom aligned realloc fallback | unix libc | Preserve Jonx fallback; test over-aligned growth |
| Files/paths | v11 libc and volume push fix | C metadata/path bridge | unix PAL extensions | Shared RAM: write/read test; broader semantics later |
| mmap/entropy | emulated mapping, fail-closed jitterentropy | no mmap; arc4random_buf with weak native fallback | entropy.resource/getentropy sources | Native entropy quality remains unaccepted; no cryptographic claim |
| Process/stdio | exec adapter, concurrent output draining | DOS process bridge, direct posixc stdio | Command/net documented ENOSYS | First milestone only direct stdio and real process exit |
| Sockets | owner-task boundary | bsdsocket bridge | stubs | Defer; do not import unsafe socket Send/Sync |
| Panic | abort and separately accepted v11 unwind | abort | abort | ARM abort first; unwind separate |
| Host/proc macros/tests | isolated wrapper; 71 host tests pass | stock pinned host compiler | same stage1 host/target | Preserve same compiler for each profile; add bounded test runner later |

The first integration slice retains our x86_64 backend and imports Jonx's
existing ARM backend through pinned source inputs, with a common build entry
and acceptance workload. This avoids rewriting ARM or destabilizing v11. It is
not yet a single std backend. Rebase/consolidation onto mainline is evaluated
after native ARM link and execution expose the actual SDK gaps.

## Available Pi inputs

Local native toolchain: `AROS/toolchains/raspi-aarch64`, Clang 20.1.0,
SDK from `AROS-20260822-raspi-aarch64-system.tar.bz2`; details and provenance
are in that directory's README and evidence. The compiler wrapper reserves
x18 conservatively; Jonx only requires that reservation on hosted macOS.
This difference is explicit, not an inferred native ABI requirement.

`AROS/documentation/vm-pool.md` records an AArch64-v1 QEMU raspi3b pilot.
Its USB storage gate is not accepted. No physical Pi model/access has been
confirmed in this session; the user has been asked. Do not write any medium.

## Plan and execution ledger

1. Pin source identities and record existing baseline. Done: 71 host tests
   pass outside sandbox (sandbox forbids fixture TCP bind).
2. Add private, non-registering Jonx sysroot creation and explicit ARM profile;
   test refusal of wrong revisions, dirty sources and existing destinations.
3. Build the shared acceptance static library and native C harness against
   the selected Pi SDK. Adapt only demonstrated SDK gaps as versioned patches.
4. Build the same acceptance workload for the retained x86_64 profile; run
   regressions with deadlines and actual Shell receipts where available.
5. Package C/no_std/std binaries and repeatable execution procedure. Report
   each execution environment separately. Physical runtime acceptance remains
   pending until real hardware access is established.

Pre-integration diagnostic: compiling our v11 `csrc/compat.c` using the Pi
Clang wrapper fails at undeclared `posix_memalign` (line 312). This is not
evidence that the function is absent from all AROS systems. The v11
`__open_CrtBase_wrapper` binding also cannot be assumed valid for native v1.
