The integrated source base is our pinned August nightly with x86_64-v11
unchanged and Jonx's actual ARM PAL imported into that same std tree. It uses
one compiler, sysroot constructor, build entry and acceptance workload.
Different ABI backends remain explicit; v11 libc bindings/glue are excluded
from ARM. The versioned Jonx patch adapts allocator, error and fs internal APIs
and refuses native socket creation until its ownership model is implemented.
This is cheaper than rebuilding a whole compiler or rewriting the ARM PAL.
Further backend consolidation onto mainline remains an evaluated follow-up.

Mainline review found `ecdc52080ac8dfc593a27888695b8fba8c836eb2` (2026-10-18):

`67f6c86` (env enumeration, volume paths, sysconf), `b9dc78f` (ISA flag ordering),
`b0f152d67e9a7c42c06ede3cba4b34ff71a8b897` (TLS for non-pthread tasks), and

## Plan and execution ledger

1. Pin source identities and record existing baseline. Done: 71 host tests
   pass outside sandbox (sandbox forbids fixture TCP bind).
2. Add private, non-registering Jonx sysroot creation and explicit ARM profile;
   test refusal of wrong revisions, dirty sources and existing destinations.
3. Build the shared acceptance static library and native C harness against
   the selected Pi SDK. Adapt only demonstrated SDK gaps as versioned patches.
4. Build the same acceptance workload for the retained x86_64 profile; run
   regressions with deadlines and actual Shell receipts where available.
5. Package C/no_std/std binaries and repeatable execution procedure. Report
   each execution environment separately. Physical runtime acceptance remains
   pending until real hardware access is established.

Pre-integration diagnostic: compiling our v11 `csrc/compat.c` using the Pi
Clang wrapper fails at undeclared `posix_memalign` (line 312). This is not
evidence that the function is absent from all AROS systems. The v11
`__open_CrtBase_wrapper` binding also cannot be assumed valid for native v1.

## Delivered implementation and execution evidence

The plan's software slice is implemented. `tools/common-sysroot.py` creates a
new private sysroot without a rustup registration; source/ABI choices are in
that constructor and `profiles/aarch64-v1-raspi.json`. The existing x86_64
target template is retained. `tools/build-acceptance.py` builds all three gates
and rejects architecture/ELF ABI mismatches, unresolved symbols and unguarded
legacy ARM sysroots. `tools/package-acceptance.py` verifies artifact hashes and
creates a private bundle without touching a guest or medium.
