# Rust AROS M0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement inline.

**Goal:** Preserve the known v11 toolchain while making isolated rebuilds safe.
**Architecture:** Work in a local Git clone under the writable AROS workspace.
Require an explicit new sysroot and a non-shared toolchain name, pin the known
nightly, and validate existing examples before changing runtime behaviour.
**Tech Stack:** POSIX shell, Python unittest, Rust nightly 2026-08-31.
**Spec:** ../specs/2026-10-15-rust-aros-renewal-design.md

## Global constraints

ABIv11 primary; ABIv1 next; x86_64 and hosted arm64 Macaros in scope.
No shared toolchain changes, no native Pi scope, no inferred runtime success.
The user selected inline execution and authorized starting the design.

## Review focus

Existing destination must remain untouched. Shared aros-nightly must not be
relinked. Wrong nightly must fail before mutation. Paths containing spaces must
work. A failed patch must not leave a registered incomplete toolchain.
